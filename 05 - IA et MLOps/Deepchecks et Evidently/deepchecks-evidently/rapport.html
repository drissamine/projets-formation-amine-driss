01

Objectif du projet

Le projet répond au sujet “Tests et Monitoring Machine Learning, Deepchecks et Evidently”. Il montre comment surveiller un système ML quand le code reste stable mais que les données évoluent. Le travail ne se limite pas à entraîner un modèle: il met en place des contrôles qualité, détecte les dérives et produit des rapports exploitables pour une gouvernance MLOps.

Question traitée

Comment vérifier qu'un modèle reste fiable lorsque les données courantes changent par rapport à une référence historique.

Outils imposés

Deepchecks pour les tests automatisés, Evidently pour le monitoring visuel de dérive.

Livrables

Données, modèle sérialisé, rapports HTML, README et scripts reproductibles.

02

Pipeline réalisé

La logique du dépôt suit une chaîne MLOps claire. Chaque étape produit une preuve concrète et réutilisable, ce qui rend le travail vérifiable par un évaluateur.

1

Données

Création de reference.csv et current.csv avec dérive simulée.

2

Modèle

Entraînement d'un pipeline sklearn et sauvegarde dans model.joblib.

3

Tests

Deepchecks contrôle l'intégrité, la cohérence reference/current et le comportement du modèle.

4

Monitoring

Evidently compare les distributions et mesure la dérive statistique des colonnes.

5

Rapports

Les résultats sont archivés dans artifacts/ sous forme de rapports HTML.

Le modèle est sauvegardé comme un artefact versionnable. C'est une bonne pratique MLOps: le modèle devient un objet réutilisable, auditable et compatible avec les étapes de test et monitoring.

06

Tests automatisés avec Deepchecks

Deepchecks sert de quality gate. Le rapport contrôle la qualité des données, compare les datasets et mesure le comportement du modèle. Le script a été amélioré pour déclarer explicitement les colonnes catégorielles et fournir une importance de variables calculée proprement.

Intégrité

Contrôle des doublons, valeurs manquantes, types, corrélations et anomalies de structure.

Validation reference/current

Détection des différences entre baseline et données courantes, avec suite train-test validation.

Évaluation modèle

Analyse de la performance, de la dérive de prédiction, de la matrice de confusion et de l'inférence.

Rapport disponible ici: artifacts/deepchecks_report.html.

08

Interprétation critique

Le projet ne cache pas les signaux négatifs. Au contraire, il les utilise comme preuve que le monitoring fonctionne. Le modèle reste exploitable pour la démonstration, mais les rapports montrent une performance limitée et une dérive de prédiction. Dans un vrai pipeline, ces alertes déclencheraient une analyse métier, un recalibrage ou un réentraînement.

Performance modèle
Dataset Accuracy F1 AUC

Ce que cela prouve

Le travail ne cherche pas à produire artificiellement un modèle parfait. Il démontre une compétence MLOps: instrumenter un modèle, détecter les changements, interpréter les alertes et produire des preuves consultables.

🗃️ Partie 2 — Création d'une table Delta

Delta Lake

2.1 Enregistrement dans Delta

Spark df.write.mode("overwrite").format("delta").saveAsTable("sales_delta")

2.2 Table externe vs Table gérée

📁 Table externe
sales_external — Chemin explicite

Caractéristique : Les données sont stockées à un emplacement spécifié (/user/hive/warehouse/sales_external). La suppression de la table ne supprime pas les données physiques.

📦 Table gérée
sales_managed — Warehouse par défaut

Caractéristique : Spark gère le cycle de vie complet. La suppression de la table supprime définitivement les données.

2.3 Comparaison

CritèreTable externeTable gérée
EmplacementDéfini par l'utilisateurWarehouse par défaut
Suppression de la tableNe supprime pas les donnéesSupprime données + métadonnées
Cas d'usageDonnées partagées entre servicesDonnées propres à l'application

4.4 Intérêt du Time Travel

Le Time Travel dans Delta Lake permet :

1. Audit et traçabilité : Chaque modification est versionnée. On peut retracer qui a fait quoi et quand.
2. Reprise après erreur : Si une mise à jour ou suppression accidentelle se produit, on peut revenir à une version antérieure facilement avec versionAsOf ou timestampAsOf.
3. Reproductibilité : Pour des analyses ou des modèles ML, on peut garantir l'utilisation exactement des mêmes données.
4. Comparaison temporelle : On peut comparer l'état des données entre différentes versions pour analyser l'impact des changements.
5. Conformité réglementaire : Conservation de l'historique complet pour satisfaire aux exigences d'audit (RGPD, SOX, etc.).
6. Data Testing : Tester des transformations sur une version passée sans affecter les données courantes.

⚙️ Partie 6 — Optimisation

OPTIMIZE / VACUUM

6.1 Commande OPTIMIZE

SQL OPTIMIZE sales_delta

Compacte les petits fichiers en fichiers plus grands et optimisés pour améliorer les performances de lecture.

6.2 Commande VACUUM

SQL VACUUM sales_delta RETAIN 24 HOURS

Supprime physiquement les fichiers de données qui ne sont plus référencés par la dernière version de la table.

6.3 Explication détaillée

OPTIMIZE

• Compacte les petits fichiers en fichiers plus grands
• Réorganise les données (Z-Ordering optionnel)
• Réduit le nombre de fichiers à scanner
• Améliore les performances de lecture

VACUUM

• Supprime les fichiers obsolètes
• Libère de l'espace disque
• Paramètre RETAIN pour garder l'historique
• Après VACUUM : plus de Time Travel possible avant la rétention

Différence clé : OPTIMIZE améliore les performances de lecture, VACUUM libère de l'espace disque. Les deux sont essentiels pour la maintenance des tables Delta en production.

Le Lazy Loading (Masterclass)

Pourquoi c'est CRITIQUE ?

Imaginez télécharger Netflix entier juste pour regarder un seul épisode. C'est ce que font les applications sans Lazy Loading.

Lazy Loading = Chargement "Paresseux". On ne télécharge le code de la page 'Admin' QUE lorsque l'utilisateur clique sur 'Admin'.

⛔ Eager Loading (Classique)

Tout est chargé au démarrage. L'application est lente à s'ouvrir.

import { AdminComponent } from './admin/admin.component'; export const routes: Routes = [ // Mauvaise pratique pour les grosses pages { path: 'admin', component: AdminComponent } ];

✅ Lazy Loading (Recommandé)

Le composant est chargé uniquement à la demande.

export const routes: Routes = [ { path: 'admin', loadComponent: () => import('./admin/admin.component') .then(m => m.AdminComponent) } ];
Exercice

À vous de jouer !

Transformez cette route "Lourde" (Catalogue) pour qu'elle utilise le Lazy Loading.

Code actuel (LENT) :

{ path: 'catalogue', component: CatalogueLourdComponent }

Votre solution (Copiez ceci) :

{ path: 'catalogue', loadComponent: () => import('./catalogue/catalogue.component') .then(m => m.CatalogueLourdComponent) }

Outils & Performance

Le Lazy Loading du Futur : @defer

C'est probablement ce que vous cherchiez avec "illading". Angular 17+ permet de charger des MORCEAUX de votre page paresseusement, pas juste des routes entières.

@defer (on viewport) { // Ce composant lourd ne chargera que si l'utilisateur scrolle jusqu'ici ! <app-gros-graphique /> } @placeholder { <div>Chargement du graphique...</div> }

L'outil de Pilotage : Angular DevTools

Pour "piloter" votre application, vous devez installer l'extension Chrome/Edge Angular DevTools.

🔍 Onglet Components

Permet de voir l'arbre des composants et d'inspecter l'état (Inputs, Outputs, propriétés) en temps réel.

⏱️ Onglet Profiler

Enregistre les cycles de détection de changement. Si votre app est lente, c'est ici qu'on voit pourquoi (trop de re-rendus).

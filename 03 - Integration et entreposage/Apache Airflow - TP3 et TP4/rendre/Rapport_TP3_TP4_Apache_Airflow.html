TP3 — Installation d'Apache Airflow

Contexte : Le TP original utilisait WSL (Windows) avec Ubuntu 24.04 et Python 3.12. L'installation a été adaptée pour Linux natif avec Python 3.13 en installant Airflow 3.2.1 (au lieu de 2.9.3) car c'est la version stable compatible avec Python ≥3.10.

Étapes d'installation

  1. Vérification de l'environnement :
    Python 3.13.12 détecté. Airflow 2.9.3 nécessite Python <3.13 → version 3.2.1 utilisée.
  2. Création du répertoire de travail :
    mkdir -p ~/airflow
  3. Environnement virtuel :
    python3 -m venv ~/airflow_env
  4. Installation d'Airflow :
    pip install 'apache-airflow==3.2.1' --constraint "https://raw.githubusercontent.com/apache/airflow/constraints-3.2.1/constraints-3.13.txt"
    ✓ Succès — 106 paquets installés
  5. Initialisation de la base :
    airflow db migrate (remplace db init d'Airflow 2.x)
  6. Lancement (mode standalone) :
    airflow standalone — lance webserver + scheduler + triggerer + API server
  7. Vérification :
    curl http://localhost:8080 → HTTP 200 OK

TP4 — Création de DAGs

Rappel : Les DAGs sont placés dans ~/airflow/dags/. Airflow 3.x utilise les imports sous airflow.providers.standard.operators.* et le paramètre schedule (et non plus schedule_interval).

Exercice 1 — Premier DAG (EmptyOperator + PythonOperator)

Fichierpremier_dag_test.py
DAG IDpremier_dag_test
Scheduletimedelta(days=1)
OpérateursEmptyOperator (start, end), PythonOperator (hello_world)
Dépendancesstart >> hello_world >> end
from datetime import datetime, timedelta
from airflow import DAG
from airflow.providers.standard.operators.empty import EmptyOperator
from airflow.providers.standard.operators.python import PythonOperator

default_args = {
    "owner": "Tesnim",
    "depends_on_past": False,
    "start_date": datetime(2025, 4, 14),
    "email_on_failure": False,
    "email_on_retry": False,
    "retries": 1,
    "retry_delay": timedelta(minutes=2),
}

dag = DAG("premier_dag_test", default_args=default_args,
          description="mon premier dag", schedule=timedelta(days=1))

def print_hello():
    return "hello workd, c'est mon premier dag"

start = EmptyOperator(task_id="start", dag=dag)
hello_world = PythonOperator(task_id="hello_world", python_callable=print_hello, dag=dag)
end = EmptyOperator(task_id="end", dag=dag)

start >> hello_world >> end

Exercice 2 — DAG avec BashOperator (parallélisme)

Fichierour_first_dag.py
DAG IDour_first_dag_
Schedule@daily
OpérateursBashOperator (×3)
Dépendancestask1 >> [task2, task3] — task2 et task3 en parallèle
with DAG(
    dag_id="our_first_dag_",
    default_args=default_args,
    start_date=datetime(2025, 4, 14, 2),
    schedule="@daily"
) as dag:
    task1 = BashOperator(task_id="first_task", bash_command="echo bonjour, ceci est le premier task!")
    task2 = BashOperator(task_id="second_task", bash_command="echo bonjour, je suis task2 et je mexécute aprés task1")
    task3 = BashOperator(task_id="thrid_task", bash_command="echo bonjour, je suis task3 et je mexécute après task1 au même instant que task2!")

    task1 >> [task2, task3]

Exercice 4 — DAG avec PythonOperator et XCom

Fichierour_dag_with_python_operator.py
DAG IDour_dag_with_python_operator_v07
Schedule@daily
OpérateursPythonOperator avec XCom push/pull
Dépendances[get_name, get_age] >> greet
Fonctionnementget_name et get_age poussent des valeurs XCom, greet les récupère et affiche "Hello Jerry Fridman, you are 19 years old!"
def greet(some_dict, ti):
    first_name = ti.xcom_pull(task_ids="get_name", key="first_name")
    last_name  = ti.xcom_pull(task_ids="get_name", key="last_name")
    age        = ti.xcom_pull(task_ids="get_age", key="age")
    print(f"Hello {first_name} {last_name}, you are {age} years old!")

def get_name(ti):
    ti.xcom_push(key="first_name", value="Jerry")
    ti.xcom_push(key="last_name", value="Fridman")

def get_age(ti):
    ti.xcom_push(key="age", value=19)

[task2, task3] >> task1

I. Analyse Stratégique & Event Storming

L'Event Storming est la pierre angulaire de notre démarche. En identifiant les événements domaine comme OrderPlaced ou StockReserved, nous capturons les changements d'état immuables qui dictent le comportement du système.

Principe de Conception : Un événement domaine est un fait passé incontestable. Toute réaction à cet événement doit être traitée soit de manière synchrone (cohérence immédiate), soit via une cohérence éventuelle (Event-Driven).

Pour ShopFlow, le découpage suit les frontières de compétences métier. La Context Map ci-dessous illustre non seulement les dépendances, mais aussi la nature du couplage (ACL, Customer/Supplier).

Justification : L'Ordering Context est le "Cerveau" de l'application. Il consomme le catalogue mais se protège de l'instabilité du système de paiement par une couche d'Anti-Corruption (ACL) garantissant que son modèle interne ne dépend pas du format JSON de Stripe ou PayPal.

III. Commandes, Acteurs & Flux de Domaine

Avant de modéliser les objets techniques, nous définissons qui agit sur le système et quelles intentions (Commandes) déclenchent les changements d'état (Événements).

A. Les Acteurs du Système

  • Client (Customer) : Déclenche les commandes de produits et les paiements.
  • Administrateur : Gère le catalogue, les stocks et résout les litiges.
  • Système (Clock/Policy) : Déclenche des actions automatiques (ex: annulation si non-paiement après 15 min).

B. Cycle Commande ↔ Événement

IV. Modélisation Tactique & Invariants

A. Définition des Agrégats (Aggregate Roots)

L'agrégat définit une frontière de cohérence transactionnelle. Toute modification au sein de l'agrégat doit laisser le système dans un état valide selon les règles métier (Invariants).

  • Aggregate Root : Order
    Attributs : ID, CustomerID, TotalAmount, Status, CreationDate.
    Invariants : Le montant total doit toujours être positif. On ne peut pas confirmer une commande sans items.
  • Aggregate Root : Product
    Attributs : SKU, BasePrice, CurrentStock, DisplayStatus.
    Invariants : Le CurrentStock ne peut pas être inférieur à zéro.

B. Value Objects (Immuabilité)

Contrairement aux entités, les Value Objects sont définis par leurs valeurs. Nous les utilisons pour encapsuler la logique métier complexe. Money gère les arrondis et les devises, tandis que OrderLine fige le prix du produit à l'instant T.

VII. Glossaire & Ubiquitous Language

Aggregate Root
L'entité "Passerelle" d'un domaine qui assure l'intégrité de tous les objets sous-jacents.
Anti-Corruption Layer (ACL)
Composant de traduction qui empêche les modèles externes de polluer le domaine métier pur.
Invariant
Règle métier qui doit rester vraie en permanence au cours d'une transaction de domaine.
Event-Driven Architecture
Modèle de communication asynchrone où les services réagissent à des événements publiés par d'autres.
